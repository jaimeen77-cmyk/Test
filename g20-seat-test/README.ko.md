**G20 Seat Test 0.1.0 · iDrive 7 실험용**

차량 화면에서 시트 상태를 확인하고, 조건을 확인한 뒤 빈 조수석의 전후 축에 한 번의 짧은 이동을 요청하는 앱입니다. 시작 상태는 조회 전용입니다. 이 버전은 사용자의 2020 G20에서 아직 시험하지 않았습니다.

**설치할 파일**

`g20-seat-test-0.1.0-usb.zip`을 풀면 다음 구조가 나옵니다. `mgu-repo` 폴더를 그대로 USB 최상위에 복사하세요.

```text
USB 최상위/
  mgu-repo/
    g20-seat-test/
      catalog.json
      g20_seat_test@0.1.0.tgz
```

MGU Store의 **USB** 페이지에서 **Seat Test (G20 experimental)**를 선택해 설치합니다. 차량의 앱 목록에 **시트 테스트 / Seat Test**가 표시되도록 만든 OAP 패키지입니다. Store가 설치된 차량의 SDK를 연결해 준비하는 방식이며, BMW SDK·펌웨어는 배포물에 포함하지 않았습니다. 실제 Store에서의 설치와 차량 화면 표시는 아직 확인하지 않았습니다.

**필요한 기존 구성**

- iDrive 7용 MGU Store와 `mgu-deploy` 0.7.11 이상.
- IterioDev의 원본 **Comfort / iteriodev-comfort 0.5.1 이상**. Store 소스 `IterioDev/car-apps`의 Tags 채널에서 제공하는 도구입니다.
- 설치 카탈로그가 위 의존성을 선언합니다. Store가 도구를 찾지 못하면 해당 소스를 추가해야 합니다. 차량이 오프라인이면 Comfort가 먼저 설치되어 있어야 합니다. Comfort 자체는 이 USB에 포함하지 않았습니다.

이 앱은 Comfort의 공개된 로컬 JSON 프로토콜을 사용하는 별도 클라이언트입니다. IterioDev의 소스나 실행 파일을 복사·변경하지 않았습니다. 기존 도구의 이용 조건은 원저작자의 라이선스를 따릅니다.

**첫 실행**

1. 차량을 정차하고 P단과 주차브레이크를 설정합니다. 조수석과 이동 경로를 비우고 순정 시트 스위치에 손이 닿는 상태에서 시작합니다.
2. **상태 새로 확인**을 누릅니다. 운전석·조수석 조절 축과 위치 카운터, 차량 속도·기어 응답을 확인합니다. `No Comfort status`, 빈 축 목록 또는 `Unknown`이 나오면 우선 기록만 저장하세요.
3. 이동을 시험하려면 **빈 조수석 확인: 한 번만 이동 허용**을 누릅니다. 이 확인은 사용자가 직접 하는 것이며, 본 앱이 착좌 센서로 빈 좌석을 판정하는 것은 아닙니다.
4. 조건이 충족되면 15초 안에 **조수석 전후 +** 또는 **-** 중 하나를 한 번 누릅니다. 첫 시험에서는 실제 이동 방향을 관찰하세요.
5. 실제로 멈췄는지 확인하고 **진단 기록 저장**을 누릅니다. 반응이 늦거나 정지에 문제가 있으면 추가 이동 요청을 보내지 마세요.

진단 값과 동적 상태 메시지는 호환성 확인을 위해 영어로 표시합니다. 고정 메뉴에는 한국어 리소스를 포함했습니다.

**이동을 허용하는 조건**

- HMI가 앱 화면의 표시와 포커스를 보고한 상태.
- Comfort가 조수석 전후 축 `SLV`를 보고하고, 기존 이동·메모리 작업이 없으며, 정차 상태를 보고한 경우.
- 기존 Easy exit가 설정되어 있지 않거나 꺼져 있고, 자동 복귀 대기가 없는 경우. 이 앱은 기존 설정을 변경하지 않습니다. 시험 중 다른 시트 제어 클라이언트를 함께 사용하지 마세요.
- 별도의 SOME/IP getter 요청으로 정확한 **속도 0과 P단**을 확인한 경우. `N_OR_P`나 속도·기어 미확인은 허용하지 않습니다. 엔진 회전수로 정차를 추정하지 않습니다.
- 상태 응답과 차량 getter 응답이 앱 기준 1.5초 이내이며, 이동 직전의 재확인도 통과한 경우.
- 사용자가 빈 조수석을 확인했고, 이전 정지 전송 실패가 없는 앱 세션.

차량 getter 응답의 시각을 검사하는 것으로, 차량 내부 센서의 측정 시각을 검증한 것은 아닙니다. 주차브레이크 체결은 사용자가 확인하며, 앱은 이를 읽지 않습니다. 필요한 getter나 HMI 이벤트가 이 차량에서 제공되지 않으면 이동이 잠긴 상태가 정상입니다. 이를 우회하는 옵션은 넣지 않았습니다.

**이동과 정지의 정확한 의미**

이 앱은 조수석 `SLV` 축의 단일 `jog` 메시지만 보냅니다. 250ms 뒤 정지를 요청하도록 예약하고, 정지 메시지는 세 번 전송을 시도합니다. 유지 명령을 반복 갱신하지 않습니다. 화면 이탈·포커스 상실·종료 시에도 본 앱이 요청한 이동의 정지를 시도합니다.

**250ms는 정지 요청 예약 시간이며 실제 모터 구동 시간의 보장이 아닙니다.** Comfort의 처리 대기·진단 통신 지연에 따라 달라질 수 있습니다. `STOP requested`와 성공한 소켓 쓰기는 물리적인 정지 확인을 뜻하지 않습니다. 세 번 모두 정지 전송에 실패하면 해당 앱 세션의 추가 이동은 잠깁니다. 정상 정지 요청 후에도 재시험에는 새 확인과 대기 시간이 필요합니다.

운전석 이동·높이·등받이·메모리 호출·Easy exit·Make room은 이 앱에서 요청할 수 없습니다. 앱의 **정지 요청 / 이동 잠금**은 Comfort의 전역 정지 요청이므로 기존 Comfort 작업도 멈출 수 있습니다.

Comfort 프로토콜에는 명령별 확인 응답이나 독점 제어 잠금이 없습니다. 따라서 다른 클라이언트·자동화와의 경쟁, 서비스 내부 대기열에서의 취소까지 이 앱이 보장하지는 못합니다.

**기록 수집**

**진단 기록 저장**은 이 앱의 데이터 폴더에 `seat-test-report.json`을 씁니다. 화면에서 확인한 축·위치, 속도·기어 응답, 명령 요청·차단·정지 전송 내역을 담습니다. VIN·로그인 정보·개인 키는 수집하지 않습니다.

MGU Store의 Phone access/로그 기능으로 이 파일을 직접 내려받을 수 있는지는 Store 버전에 따라 다릅니다. 해당 기능에 파일이 없으면 차량의 SSH에서 앱 데이터 폴더를 찾아 복사합니다. 설치 시 할당되는 앱 UID는 차량마다 다르므로 경로를 고정하지 않았습니다.

```sh
find /var/opt -name seat-test-report.json -type f 2>/dev/null
```

예를 들어 출력된 경로가 `/var/opt/public/oap/oap_12345/data/seat-test-report.json`이라면 PC에서 다음처럼 복사합니다. 주소·키·경로는 실제 환경의 값으로 바꿉니다. 키 파일은 채팅으로 보내지 마세요.

```sh
scp -i /path/to/mgu_key root@MGU_IP:/실제/경로/seat-test-report.json ./seat-test-report.json
```

`seat-test.log`에는 앱 초기화와 UI 오류를 기록합니다. 설치 실패는 먼저 MGU Store 설치 로그를 확인하세요.

**제거와 개발 파일**

MGU Store의 **Installed → Seat Test → Remove**로 앱을 제거합니다. Comfort는 다른 앱이 사용할 수 있는 별도 도구이므로 필요 여부를 Store에서 따로 판단합니다.

소스 묶음에는 외부 패키지 설치 없이 실행할 수 있는 빌드·테스트가 들어 있습니다.

```sh
node test/test.js
python3 tools/build.py
python3 test/package_check.py
```

모의 검사 결과는 `TEST_RESULTS.md`에 기록했습니다. 차량 SDK·네이티브 바인딩·실제 시트에 대한 시험 결과로 해석하면 안 됩니다.
